# Benchmark Redo Results

Re-running all benchmarks after the fused-RMSNorm gradient-zeroing fix and
t_min tuning (0.05 → 0.1). All runs on CUDA (RTX 4060).

---

## 1. Setup

| | |
|---|---|
| Corpus | 67.5 MB C code (`data/train.bin`), 3.7 MB held-out (`data/heldout.bin`) |
| Model (toy) | BLT: local encoder + global patch transformer + local decoder, 2 layers each, embed 64 / hidden 128, ~300k params |
| Model (at-scale) | Same architecture, embed 128 / hidden 256, W=96, ~3.5M params |
| Training | SGD, lr 0.05 with x0.3 decay at 60%/85% of the schedule, gradient-norm clip 5.0, batch = one window |
| Diffusion schedule | t-min=0.1, mask-loss warmup 10k steps, cap 0.3 |
| Quality metric | **BPB** - bits per byte of held-out next-byte prediction (lower is better; 8.0 = random guessing) |
| Diffusion quality | **masked-cell top-1** - accuracy of predicting bytes in a masked future block |
| Speed metrics | **NFE** - forward passes of a submodule per generated byte; wall-clock |
| Speed quality | **agreement** - fraction of generated bytes identical to what plain greedy produces |

Two toy-scale checkpoints (3 seeds each for BLT-D):

- **plain** - standard next-byte objective only (`runs/plain_40k.fblt`)
- **bltd** - combined next-byte + masked-block diffusion objective, mask-loss cap 0.3 (`runs/bltd_l03_40k.fblt`)

- Gradient-zeroing fix: all 8 norm-weight gradient types zeroed (encoder norm1/2/cross, global norm1/2, decoder norm1/2/cross)

- lr-decay = x0.3 at 60%/85%

### 5.2 — Gentle late mask-loss ramp

Trained with `--mask-late-step 28000 --mask-late-scale 0.5` (ramp from 0.3→0.5 in last 30% of training). BPB=2.124, masked_acc=99.8%.

**BLT-S verification on late-ramp model vs standard BLT-D:**

| Config | Standard BLT-D | Late ramp (0.3→0.5) | Change |
|---|---:|---:|--------|
| k=4 acceptance | 0.662 | 0.541 | -0.12 (worse) |
| k=8 acceptance | 0.436 | 0.325 | -0.11 (worse) |
| k=16 acceptance | 0.259 | 0.184 | -0.08 (worse) |
| DV B=8 acceptance | 0.304 | 0.180 | -0.12 (worse) |

**Conclusion:** Gentle ramp makes BLT-S verification *worse*, not better. The original finding holds: higher mask-loss weight hurts BLT-S acceptance. The standard mask_scale=0.3 is the right operating point — no benefit to raising it late in training.

### 8.4 CPU baselines

## 6. Conclusions

Plain BLT is the better language model at every scale tested. BLT-D
trades ~0.3 BPB at toy scale and ~0.3 BPB at 3.5M params for saturated
masked-block prediction. The mask-loss weight cap at 0.3 keeps most
causal quality. At 3.5M params, the late schedule (ramp to 0.5 in last
30%) ties with base on inference acceptance, unlike the old pre-fix
numbers where it was worst.

On inference, BLT-S gives exact generation ~5x faster at toy scale. BLT-DV
does the same at 0.6-1.0 decoder passes per byte; one-step diffusion
+ verify is the best variant. At 3.5M params the trade-off is sharper:
late has best BPB (2.03) and ties for best acceptance (0.22). All
qualitative rankings improved or held with the gradient fix.

Verified generation is boundary-conditioned. Fixed-stride patching at
inference destroys agreement (0.13-0.26). Content-driven (entropy) patching
is essential.

Architecture-wise, decoder depth doesn't matter for training quality at
3.5M params (1/2/3 layers within 0.1 BPB). Cross-attention placement
increased variance (xlast BPB range 2.22-2.88). Entropy patching hurts at
both scales. A gentle late mask-loss ramp (0.3→0.5) made BLT-S verification
worse, not better — mask_scale=0.3 is the right operating point.

## 7. Reproducing

Toy-scale training (checkpoints used in Sections 2-5):

```bash
make CUDA=1 train-blt-d
bin-cuda/train_blt_d --corpus data/train.bin --eval-corpus data/heldout.bin \
    --eval-windows 300 --steps 40000 --diffusion 0 --lr-decay 1 --seed 7 \
    --save-weights runs/plain_40k.fblt --backend cuda
bin-cuda/train_blt_d --corpus data/train.bin --eval-corpus data/heldout.bin \
    --eval-windows 300 --steps 40000 --diffusion 1 --t-min 0.1 \
    --mask-warmup 10000 --mask-scale 0.3 --lr-decay 1 --seed 7 \
    --save-weights runs/bltd_l03_40k.fblt --backend cuda
```

Inference benchmark:

```bash
make CUDA=1 bench-infer
```

At-scale sweep (27 runs, ~12 hours on CUDA):

```bash
tools/run_at_scale_sweep.sh --backend cuda
```

CUDA micro/meso/macro:

```bash
make CUDA=1 bench-cuda
```
