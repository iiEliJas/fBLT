# BLT-S Verification Is Unsound: the Decoder's Latent Assignment Is Anti-Causal

**Status: CONFIRMED — root cause identified, no fix implemented.** Under greedy decoding BLT-S
(`blt_generate_greedy_selfspec`) is *not* byte-identical to plain greedy BLT
(`blt_generate_greedy`), and cannot be made so by correcting the accept/reject logic. Algorithm 2
in the paper is implemented faithfully; the soundness assumption it rests on is violated upstream,
in the decoder's cross-attention latent assignment.

Reproduces deterministically on CPU with `runs/tinystories_840k/tinystories.fblt` and
`runs/entropylm/entropy_lm.fblt`. First divergence at the **second** generated byte with `k >= 2`.
Confirmed on both entropy patching and `--fixed-patches`.

This is not a deviation from either paper. `fast_bltPAPER.md` line 84 asserts the guarantee
("Under greedy decoding, this guarantees that verified outputs are identical to standard
autoregressive decoding"), and line 391 scopes it to greedy only. The guarantee simply does not
hold for this implementation, and the paper is silent on the mechanism that breaks it.

## Origin

BLT-S output was observed to diverge from plain greedy almost immediately and to be of comparable
quality, which should be impossible under greedy verification. The investigation ran in the order
proposed: a self-consistency check first, to separate the bug class (logic vs. numerics) before
auditing the algorithm line by line.

## Step 1 — self-consistency check, and why it cannot decide the question

The proposed check: take BLT-S's own output, run **one** fresh full-context forward pass through
`E`, `G`, `D` over the whole sequence using the Verify computation path, and compare every committed
byte against `argmax(logits row p-1)`.

Implemented as `csrc/tools/selfspec_audit.c` (CMake target `selfspec_audit`). On BLT-S's 80-byte
output with `--prompt-len 16`:

```
audited positions: 64    mismatches: 8    first mismatch byte offset: 24
margins at mismatches: 1.29, 3.68, 0.38, 2.89, 1.09  (large — not near-ties)
```

So on its face: mismatches with comfortable margins, i.e. a real bug rather than float-reordering
noise. **That conclusion does not survive the control.** Running the identical audit against plain
greedy's *own* output — which is the greedy fixed point by construction — gives *more* mismatches:

| Audited file | Mismatches / 64 | First mismatch |
|---|---|---|
| `g_ref.bin` — plain greedy output | **20** | 17 |
| `g_fix.bin` — plain greedy, `--fixed-patches` | **23** | 17 |
| `selfspec.bin` — BLT-S, `k=8` | 8 | 24 |
| `s_k1.bin` — BLT-S, `k=1` | 19 | 17 |

Plain greedy "fails" the self-consistency check worse than BLT-S does. A single whole-file forward
pass is therefore **not a valid reference frame** in this codebase, and the mismatch count is not
evidence of anything on its own. The reason is the bug itself: the decoder's prediction at position
`p-1` is not a function of `x[0..p-1]` alone, so re-running the whole file through the model does
not reproduce the sequence the model itself produced. This is the one place where the step-1
framing needs correcting, and the reason is the finding rather than a flaw in the check.

## Step 2 — Algorithm 2 audit: every listed item passes

`blt_verify_draft` (`csrc/infer/self_speculation.c:82-183`) against Algorithm 2
(`docs/fast_bltPAPER.md:365-383`):

| Item | Verdict |
|---|---|
| Loop bound / indexing: `i` from `l+1` through `l+r`, `x'_i` vs `y_{i-1}` | **Correct.** `for (p = l; p < cand_len; p++)` with `argmax(rows + (p-1)*vocab_size)`; `cand_len == l+r` |
| Break immediately on mismatch | **Correct.** `x[p] = pred; return p+1;` returns before touching later draft bytes |
| No-mismatch free byte uses `y_{i-1}` at `i = l+r+1` | **Correct.** `x[cand_len] = argmax(rows + (cand_len-1)*vocab_size)`, guarded by `cand_len < target_len` |
| Patcher consistency: full-candidate vs. incremental segmentation | **Correct, and not the bug.** Every boundary rule in `csrc/models/patcher.c:6-35` is causal in `i` (newline at `i`, `H_i`, `H_i - H_{i-1}`, running patch length), so segmentation is prefix-stable and the forced split preserves all earlier boundaries |
| Draft-phase `D_0` conditioning on the last available latent | **Correct.** `draft_step` reads `d0_embed_weight[draft[m-1]]` with `pos == cache->self_len` asserted (`self_speculation.c:333,341`); no stale or misindexed latent |

Patcher consistency is additionally ruled out empirically: BLT-S diverges identically under
`--fixed-patches`, where boundaries are fixed stride-4 and completely content-independent.

## The finding

`blt_patch_decoder_latent_at` — `csrc/ops/patch_pool_cpu.c:114-127`:

```c
if (pos < start + patches[j].length) {
    if (pos + 1 == start + patches[j].length) return j;   // final byte  -> own latent j
    return (j == 0) ? 0 : j - 1;                            // non-final  -> previous latent j-1
}
```

This is the "paper rule" from Fast-BLT 3.1.1. It selects which patch latent a decoder byte row
cross-attends to, and the decoder cross-attention mask is strict group-id equality
(`csrc/infer/kv_cache.c:234`), so each row attends to **exactly one** latent chosen by this rule.

The rule keys on whether a byte is the **last** byte of its patch. That is a function of a patch
boundary lying to the *right* of the byte — i.e. of the very byte being predicted. **The decoder's
next-byte prediction at position `p` is therefore not a function of `x[0..p-1]` alone.** The
causality that Algorithm 2's equivalence guarantee depends on is absent, and the guarantee fails
before the accept/reject loop is ever reached.

Concretely, per position `p` plain greedy needs a patch boundary at `p`:

- Greedy at `cur_len = p` segments `x[0..p)`, whose last patch ends at `p-1`. Row `p-1` is final, so
  it reads its own patch's latent — a latent pooled over bytes ending exactly at `p-1`. This happens
  for *every* `p`.
- Verify's candidate is `x[0..l+r)`. It has a boundary at `l` and at `l+r`, plus natural breaks —
  **not** at `l+1, l+2, …, l+r`. For any `p` that is not a candidate boundary, row `p-1` is
  non-final and reads latent `j-1` instead: a latent pooled over a *different, truncated* byte span.

The forced patch boundary at `l` (`self_speculation.c:109-132`) supplies exactly one of the `r`
boundaries that are needed. Its own comment concedes the symptom it was written to paper over
("without this, the prefix patch absorbs draft bytes and verification diverges from greedy").

### Arithmetic proof

Patch tables printed by `selfspec_audit --print-patches` on the BLT-S output, and the resulting
latent index for position 16 under `blt_patch_decoder_latent_at`:

```
natural segmentation:   patch 3=[11,16)  patch 4=[16,20)  ->  latent_at(16) = 4-1 = 3
--force-l 17:          patch 3=[11,16)  patch 4=[16,17)  ->  latent_at(16) = 4     (16 is final)
```

The latent index moves purely because the boundary moved from 20 to 17. The prediction at position
17 follows it:

| Run | argmax @ 17 | margin |
|---|---|---|
| natural segmentation (what BLT-S commits) | `0x74` `t` | 4.79 |
| `--force-l 17` (byte 16 final = greedy's context) | `0x77` `w` | 0.91 |
| **plain greedy, `cur_len = 17`** | `0x77` `w` | — |

`0x77` is exactly the byte plain greedy produces. The *only* difference between the two audit runs is
where the patch boundary sits, and that alone decides whether BLT-S agrees with greedy. This A/B is
causality-respecting, unlike the whole-file check in Step 1.

### Draft-window scaling

Each additional drafted byte requires one more boundary that the candidate does not have, so the
failure should arrive earlier as `k` grows. It does:

| `k` | First divergent generated byte |
|---|---|
| 1 | #13 |
| 2 | #1 |
| 3 | #1 |
| 4 | #1 |
| 8 | #1 |

`k=1` needs two boundaries and the candidate supplies both, so it survives a long way; `k>=2`
fails at the first position after the first natural break. Divergence at generated byte #1, not at
byte #0, because byte #0 is predicted by row `l-1` — a genuine prefix row, whose latent is
unaffected. Byte #1 is predicted by row `l`, the first draft row, and that is the first row whose
latent is wrong.

## Why the existing equivalence gate does not catch this

`tests/unit/infer/unit_self_speculation.c:455` (`run_selfspec_equivalence_trained`) does assert
byte-identity against plain greedy across 19 prompts x `{4,8,16}` x `{ZEROS,LEARNED}`. Its own
comment states the limitation:

> Warmup toward memorized continuations: large logit margins make the greedy argmaxes robust,
> mirroring the regime where the paper's equivalence guarantee applies.

It overfits three short snippets for 300 steps, so the wrong latent usually fails to flip the
argmax. It is a smoke test for gross breakage, not a guard on this property. Nothing in the suite
exercises a trained checkpoint at a scale where margins are small.

## Relationship to `forced_boundary_patches.md`

That document measured the cost of forced boundary closures: for 1-byte patches, final-byte
accuracy collapses from 96.98% (natural) to 8.33% (forced). The hack at `self_speculation.c:109`
forces a boundary closure at every commit point, so it walks straight into the pathology already
quantified there — and, per the finding above, does not even buy equivalence in exchange. The
symptom was visible in the ablation notes before the mechanism was isolated.

## Fix directions

Not implemented. The constraint is that the row-`p-1` prediction must not depend on a boundary right
of `p-1`.

1. **Make the latent assignment causal.** Drop the final-byte special case so every byte of patch
   `j` reads a latent pooled only from bytes `< ` its own position. This changes the trained
   semantics of `d0_embed_weight` consumers and the cross-attention targets, so it needs a
   retraining decision, not just a code edit.
2. **Re-segment per verified position.** Have Verify's reference prediction for each `p` use the
   segmentation of `x[0..p)`. Provably equivalent to greedy, but costs an encoder/global pass per
   drafted byte — exactly what BLT-S exists to avoid.
3. **Restrict verification to positions the candidate can certify** — i.e. only accept at positions
   that happen to be candidate patch boundaries, and fall back to a plain AR step otherwise. Cheap
   to try, and degrades to plain greedy rather than to wrong output.

Option 3 is the cheapest experiment and would confirm the mechanism by construction: if BLT-S then
matches greedy while acceptance drops, the boundary-dependence is the whole story.

## Open loose end

`k=1` still diverges at generated byte #13 despite the boundary accounting predicting it should be
exact (two boundaries required, two supplied). Not root-caused. Candidates are the `r_eff == 0`
unverified tail at `self_speculation.c:426-432`, which commits a byte from the KV-cache
`prefill_argmax` with no verification at all, or an interaction with the patcher's
`reset_on_newline` rule. Recorded rather than guessed.

## Reproducing

```bash
cmake --build build --target infer selfspec_audit -j$(nproc)

CKPT=runs/tinystories_840k/tinystories.fblt
ELM=runs/entropylm/entropy_lm.fblt
printf 'Once upon a time' > /tmp/prompt.txt
COMMON="--checkpoint $CKPT --embed 256 --hidden 512 --enc-layers 2 --glob-layers 6 \
        --dec-layers 2 --backend cpu --cross-attn all --entropy-lm $ELM --new-bytes 64 --seed 11 \
        --prompt-file /tmp/prompt.txt"

# Divergence
./build/infer $COMMON --method greedy   --output /tmp/g.bin
./build/infer $COMMON --method selfspec --k 8 --output /tmp/s.bin
cmp /tmp/g.bin /tmp/s.bin

# Draft-window scaling
for K in 1 2 4 8; do
  ./build/infer $COMMON --method selfspec --k $K --output /tmp/k$K.bin
  cmp /tmp/g.bin /tmp/k$K.bin
done

# Latent-boundary A/B
./build/selfspec_audit --checkpoint $CKPT --entropy-lm $ELM --embed 256 --hidden 512 \
  --enc-layers 2 --glob-layers 6 --dec-layers 2 --cross-attn all \
  --file /tmp/s.bin --prompt-len 16 --print-patches
./build/selfspec_audit --checkpoint $CKPT --entropy-lm $ELM --embed 256 --hidden 512 \
  --enc-layers 2 --glob-layers 6 --dec-layers 2 --cross-attn all \
  --file /tmp/s.bin --prompt-len 16 --print-patches --force-l 17
```

`selfspec_audit` flags: `--file`, `--prompt-len`, `--force-l N` (replicate Verify's forced boundary
at `N`), `--print-patches`, `--margin-threshold F` (tag near-ties), `--cross-attn all|last`,
`--seed`. The mismatch summary is not a verdict on its own — see Step 1.
